# Попутно — фронтенд

React + TypeScript + Vite. Полный путь: вход / регистрация → код из письма → условия перевозки → сравнение → подробный отчёт → история.

## Запуск

Из корня репозитория в первом терминале:

```bash
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app.main:app --reload --host 127.0.0.1 --port 8000
```

Если `.venv` ещё нет, сначала выполните `python3 -m venv .venv`.

Во втором терминале:

```bash
cd frontend
npm ci
npm run dev
```

Откройте **http://localhost:5173/**. Фронт по умолчанию обращается к API на том же имени хоста, порт 8000. Не смешивайте `localhost` и `127.0.0.1` в адресах фронта и API. Нужен Node.js 20.19+ или 22.12+.

Для другого API скопируйте `.env.example` в `.env.local` и измените `VITE_API_URL`. Затем перезапустите Vite. Адрес фронта должен быть в `ALLOWED_ORIGINS` бэка. Vite использует порт 5173 строго: если он занят, остановите прежний процесс.

## Подтверждение почты

Регистрация и вход работают с существующим сервером. После регистрации нужен шестизначный код. Без SMTP сервер по умолчанию создаёт локальное тестовое письмо, а не отправляет его на настоящую почту.

Чтобы увидеть код, в третьем терминале из корня репозитория:

```bash
source .venv/bin/activate
python -m backend.show_test_mail
```

Проверьте получателя письма и введите код на странице. См. [настройку SMTP](../backend/auth/MAIL.md).

Пароль и токен сессии фронт не сохраняет в браузерное хранилище. Cookie сессии выставляет сервер. Незавершённое подтверждение хранится в `sessionStorage` вкладки, чтобы пережить обновление страницы; пароль туда не записывается.

## Что работает

- Вход, регистрация, подтверждение почты, повторная отправка кода, выход и восстановление cookie-сессии.
- Поиск населённых пунктов по сети России, промежуточные остановки с погрузкой, выгрузкой и временем обработки, несколько грузов с индивидуальными требованиями.
- Разовая отправка, регулярный график с произвольным интервалом или список дат. Время вводится по Москве; текущий сервер допускает до 64 отправок в расчёте.
- Новый расчёт использует `POST /network/russia/calculations` (`engine: russia`, схема ответа 1.0). Справочники загружаются из `/network/options`, населённые пункты — из `/network/russia/options` с поиском на сервере.
- Название груза вводится свободно. Если сервер возвращает `needs_clarification`, форма показывает вопросы и сохраняет заполненные условия. Свойства неизвестного груза автоматически не выдумываются.
- Сравнение строится по массиву `candidates`: варианты маршрутов, виды транспорта, стоимость, сроки, ограничения и рекомендация сервера. Раскрытая колонка и рекомендованный вариант независимы; фигурная перемычка следует за выбранной колонкой.
- В отчёте показаны начисления, этапы маршрута, доставки отдельных позиций и источники из ответа API. Неполная стоимость не выдаётся за полную, отсутствующая — за нулевую. Ограниченный поиск, сценарные данные и отсутствие подтверждения бронирования обозначены явно.
- Разница в стоимости вычисляется относительно самого дешёвого допустимого автомобильного варианта среди найденных в этом ответе. Если такого варианта нет, сравнение с автобазой не показывается.
- Возврат к заполненным условиям, новый пустой расчёт, сохранение результата при обновлении страницы и переходы браузера назад/вперёд.
- История хранит полные снимки запроса, ответа и названий грузов **локально в браузере**, отдельно для ID пользователя и адреса API. Она не синхронизируется между устройствами. Сохранённые результаты не пересчитываются при открытии.
- Панель ассистента использует `POST /assistant/chat` с текущей сессией. Для продолжения уточнений передаёт ответные `draft` и `pending`. Пилотный расчёт, расчёт по сети России и проверка гипотез на опорных коридорах открываются в разделе «Расчёт». Справка и специализированные тарифные расчёты отображаются в чате вместе с источниками. Для ответов запустите Ollama с моделью из [настроек ассистента](../assistant/ASSISTANT.md).

Старые локальные снимки ответа `/calculations` продолжают открываться в прежнем отчёте. Новые снимки используют сетевой расчёт; сохранённые результаты не преобразуются и не пересчитываются. Плановый объём — сумма масс позиций, умноженная на число отправок; тарифы и маршруты определяет сервер.

Чекбокс согласия обязателен в форме регистрации. В текущем контракте сервер не принимает отдельное поле согласия; для сохранения его версии и времени понадобится расширение API.

## Сборка и проверка

```bash
cd frontend
npm run build
npm run preview
```

`build` проверяет TypeScript и собирает `dist/`. Для работы предпросмотра также нужен запущенный API; адрес предпросмотра добавьте в `ALLOWED_ORIGINS`, например `http://localhost:4173`.

Обновлённый интерфейс проверен в headless Chrome с настоящим FastAPI и отдельной временной базой: регистрация и подтверждение, поиск города, сетевой расчёт, переключение отчётов и фильтров, уточнение неизвестного груза, произвольный регулярный интервал, отправки по датам, несколько грузов и остановка с погрузкой/выгрузкой. Проверены лимит отправок, неполные данные без нулевых цен, история новых и старых расчётов, обновление страницы, ошибка API и повторный вход с сохранением формы. Внешний вид проверен на десктопе.

Основные файлы:

- `src/main.tsx` — сессия, справочники и переходы.
- `src/Auth.tsx` — авторизация.
- `src/ConditionsForm.tsx`, `src/SettlementPicker.tsx` — форма и поиск населённых пунктов.
- `src/networkApi.ts`, `src/model.ts` — новый контракт, условия и подготовка запроса.
- `src/Results.tsx` — сетевой результат, отчёт и общая история.
- `src/LegacyResults.tsx`, `src/legacyModel.ts` — совместимость со старыми сохранёнными расчётами.
- `src/history.ts`, `src/Assistant.tsx`, `src/api.ts` — локальные снимки, панель помощника и HTTP-запросы.

## Передача следующему фронтендеру

Основной сценарий подключён к новому сетевому API. При дальнейших изменениях сохраняйте независимость рекомендации сервера и раскрытого отчёта, обработку уточнений груза и совместимость старой локальной истории. Отсутствующая или неполная стоимость не должна отображаться как нулевая полная цена.

Оставшиеся задачи:

- Проверить и доработать мобильный сценарий после расширения формы; текущая визуальная проверка ориентирована на десктоп.
- Подключить серверную историю и ИИ-ассистента, когда появятся соответствующие API. Сейчас история локальная, отправка сообщений ассистенту недоступна.
- Добавить постоянные автоматические браузерные тесты в репозиторий. Выполненные проверки описаны выше; временные проверочные скрипты в репозиторий не включены.
- Проверить развёрнутое приложение: адрес API, разрешённые origins, cookie-сессию, SMTP и полный путь от регистрации до открытия истории.
- Если требуется сохранять факт согласия на обработку данных, согласовать с бэкендом версию и время согласия.

Для проверки изменений выполняйте `npm run build` и проходите сценарий: вход → заполнение условий → расчёт → раскрытие другой колонки → история → сохранённый результат. Отдельно проверяйте уточнения неизвестного груза, несколько грузов и ошибку API.
