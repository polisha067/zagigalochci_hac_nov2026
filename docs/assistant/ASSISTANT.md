# Контракт транспортного ассистента

Чат использует пять движков из `POST /calculations`. Пилотный черновик
поддерживает один груз между двумя городами с разовым или регулярным
расписанием. Сетевые расчёты принимают параметры своих движков, включая
несколько грузов и остановки. Справки используют версионированные снимки.

## HTTP

`POST /assistant/chat` доступен после входа подтверждённого пользователя.
Из браузера передавайте JSON и `credentials: "include"`. Ручка использует
текущие ограничения по Origin и авторизации. Ответы защищены от кеширования.
Контракт доступен в Swagger по адресу `http://localhost:8000/docs`.

```json
{
  "message": "Нужно возить по 10 тонн муки из Москвы в Брянск",
  "draft": null,
  "pending": null
}
```

В `message` допустимо до 2000 символов после удаления внешних пробелов. В первом
запросе `draft` и `pending` можно опустить. Для продолжения передавайте оба
поля из последнего ответа без преобразования. `draft` содержит пилотный
черновик, а `pending` хранит имя другого инструмента и параметры, которые
успели собрать до уточнения. Для нового диалога сбросьте оба поля.

Черновик содержит `origin`, `destination`, `cargo_type`, `weight_tonnes`,
`volume_m3`, `splittable`, `schedule`, `max_delivery_hours` и
`capacity_basis`. До уточнения значение может отсутствовать или быть `null`.
У `schedule` допустимы режимы `once` с `ready_at` и `regular` с
`start_at`, `end_at` и `frequency`. Даты передаются с часовым поясом.
Параметры периода и единиц совпадают с контрактом расчёта.

## Ответ и обработка ошибок

Ответ содержит `kind`, `reply`, `draft`, `pending`, `missing_fields`,
`tool`, `engine`, `calculation`, `result` и `sources`.

| `kind` | Поведение фронта |
|---|---|
| `clarification` | Показать вопрос и сохранить `draft` и `pending`. `missing_fields` содержит пути к полям, например `schedule.frequency`. Если вопросы вернул движок, в `calculation` есть его ответ с `input_status: "needs_clarification"`. |
| `calculation` | Результаты `pilot` и `russia` открываются на дашборде. Речные, авиационные и трубопроводные результаты отображаются в чате. Поле `engine` определяет формат `calculation`, который совпадает с ответом `POST /calculations`. |
| `information` | Показать `reply`, источники и `result`, если он есть. Успешный `compare_corridor_hypotheses` также обновляет дашборд: три схемы берутся из `result.rows`, условия расчёта — из `result.details`. |

Если в `missing_fields` пришло `intent`, покажите вопрос из `reply` и сохраните
черновик. Это выбор между новым расчётом и изменением текущего. Кнопка
«Новый расчёт» может сбросить черновик на `null`.

Текст строится сервером из тех же результатов, что и таблицы. Верхнеуровневые
`sources` приводят источники расчётов и справок к общему формату. Используйте
`url` для внешней ссылки и `path` для относительного пути внутри проекта.
При наличии `section` и `date` отображайте их рядом с названием источника.

## Движки и справки

| Движок | Назначение |
|---|---|
| `pilot` | Сравнение авто и авто → ж/д → авто на синтетическом каталоге. |
| `network` | Маршруты и цепочки по хабам и услугам выбранной сети, включая речной сценарий Красноярск ↔ Дудинка. |
| `russia` | Сценарная сеть по населённым пунктам России с автоматическим выбором хабов. |
| `chukotavia` | Плановые варианты на даты готовности груза и оценка опубликованной тарифной составляющей. |
| `pipeline` | Опубликованная часть тарифа товарной нефти по направлению, массе нетто и дате отправки. |

Справочные инструменты работают с наблюдениями о связности городов, датами
рейсов FESCO, ставками и рейсами ЧукотАВИА, речным сценарием, трубопроводными
ставками и операциями, справочником Росморпорта, статистикой АСОП и
макросценариями Транспортной стратегии. Происхождение наборов описано
в [data_sources/README.md](../data/README.md).

Опубликованный тариф покрывает только заявленные компоненты. Справка о рейсе
показывает расписание снимка. Расчётные ставки, навигация, время операций и
ресурсы могут быть сценарными. Для приёма груза и бронирования нужно
подтверждение перевозчика.

Рейтинг регионов требует отдельного валидированного снимка
`data_sources/strategy/regional-forecast.json` с базовым и прогнозным
объёмом по регионам, методикой и ссылкой на источник. В репозитории такого
снимка нет, поэтому запрос возвращает `status: "unavailable"`. Общероссийские
показатели доступны отдельной справкой.

Ошибки возвращаются в формате `{"error":{"code":"…","message":"…","fields":[]}}`.
У чата свой лимит 30 сообщений в минуту на пользователя. Счётчик запусков
расчёта общий с формой. При превышении любого лимита действует
`429` с `Retry-After`. Недоступность обработчика сообщений и таймаут
возвращают `503 assistant_unavailable`. Некорректное действие обработчика
возвращает `502 assistant_invalid_response`. При временной недоступности
ассистента пользователю доступна форма расчёта.

## Запуск с Ollama

[20 готовых запросов для чата](ASSISTANT_EXAMPLES.md) включают расчёт двух гипотез
на опорных коридорах и расчёты по снимкам перевозчиков.

Установите [Ollama](https://ollama.com/download) и скачайте модель:

```powershell
ollama pull qwen3:8b
```

Если Ollama ещё не запущен, выполните `ollama serve`. После установки
зависимостей из `backend/requirements.txt` запустите API из корня репозитория:

```powershell
python -m uvicorn backend.app.main:app --reload
```

`OLLAMA_URL`, `OLLAMA_MODEL` и `OLLAMA_TIMEOUT_SECONDS` можно указать в
`backend/.env`. По умолчанию используются `http://127.0.0.1:11434`,
`qwen3:8b` и 90 секунд ожидания ответа. API открывает соединение с Ollama
только при первом запросе чата.

При ошибке Ollama `cudaMalloc failed: out of memory` можно ограничить
контекст и число слоёв модели на видеокарте. Для локальной `qwen3:8b`
пример настроек в `backend/.env` выглядит так.

```dotenv
OLLAMA_NUM_CTX=4096
OLLAMA_NUM_GPU=24
```

После изменения файла перезапустите бэкенд. Часть модели будет работать на CPU.

Qwen сначала выбирает инструмент, затем получает его схему и извлекает
параметры из реплики. Для уточнения она получает соответствующий черновик.
Сервер валидирует параметры и вызывает существующий движок или читает снимок.
Для `compare_delivery` сервер проверяет поля,
обновляет или сбрасывает черновик, проверяет город и груз по каталогу и при
полном наборе условий запускает существующий калькулятор. При смене груза
уточняются зависящие от него параметры. При изменении веса известный объём
партии проверяется заново. Даты без указанного смещения относятся к
`Europe/Moscow`. Для границ регулярного периода дата без времени означает
полночь, правая граница исключается. Для разовой отправки нужно время
готовности. Смещение отображается в тексте результата.

Проверки с `httpx.MockTransport` воспроизводят обмен по API Ollama и
выполняют настоящий расчёт. `create_app(assistant_planner=…)` оставляет
возможность отдельно тестировать HTTP-контракт.

Для вопросов о грузовой ставке укажите перевозчика ЧукотАВИА. Ассистент использует
`lookup_air_freight_tariff`. Тариф и ссылка на его источник берутся из того же
снимка, что и для [авиационного API](../calculations/modes/AVIATION.md). Ответ имеет
`kind: "information"` и сохраняет черновик. Если дата не указана, используется
дата снимка. При наличии веса и объёма сервер оценивает тарифную составляющую
обычного груза. Полная стоимость, свободное место и приём груза требуют
подтверждения перевозчика.

Пример вопроса «Сколько стоит отправить ЧукотАВИА 100 кг книг объёмом
0,5 м³ из Анадыря в Провидения 10 ноября 2026 года?». По снимку ставка
758,84 ₽/кг с НДС, оценка тарифной составляющей 75 884 ₽ с НДС.

## Контрольный расчёт

Из корня репозитория в Python-окружении с установленными зависимостями:

```powershell
python -m backend.run_calculation
python -m unittest discover -s tests -t . -p "test_*.py"
```

Контрольная версия расчётного ядра — `cc2b302`, каталог — `synthetic-pilot-v2`.
Запрос [Москва → Брянск](../../backend/examples/calculation-request.json) даёт 8 отправок
и 80 т в синтетическом сценарии. При лимите 48 ч результат рекомендует
договорное авто за 208 000 ₽. При лимите 168 ч рекомендует ж/д схему
за 140 000 ₽ со сроком 156 ч. В тесте чата результат сравнивается с формой
на одинаковых условиях.

Для прогона через подключённую модель отправьте от авторизованного пользователя
следующие реплики в порядке списка. Между запросами передавайте ответный `draft`.

1. «Нужно возить по 10 тонн муки из Москвы в Брянск». Ожидается `clarification`.
2. «Дважды в неделю с 9 ноября 2026 до 7 декабря 2026, конец не включаем.
   До 48 часов, партию можно делить, проверяем по массе». Ожидается `calculation`
   с 8 отправками, 80 т и рекомендацией `contract_road`.
3. «А теперь до семи дней». Ожидается `calculation` с теми же 8 отправками и
   80 т, новой рекомендацией `road_rail_road` и лимитом 168 часов в черновике.
