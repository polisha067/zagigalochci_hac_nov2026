# Авиация ЧукотАВИА: расчёт и API

«Аэрогруз» исключён из авиационного набора. Подключён адаптер опубликованных тарифов
и расписаний ЧукотАВИА: `/network/aviation/calculations`, а также общий `/calculations`
с `engine: "chukotavia"`. Это оценка тарифной составляющей и плановых вариантов,
не подтверждённое бронирование и не полная стоимость от двери до двери.

## Данные

Снимок 08.11.2026: 17 страниц официального сайта, 14 PDF-вложений скачаны.
Из вложений два пассажирских файла исключены из грузового расчёта.

- 156 направленных маршрутов, две версии тарифов: 312 строк.
- 114 строк годовых расписаний Ан-24/Ан-26, DHC-6 и Ми-8.
- 136 тарифных направлений сопоставлены с датами и временем; 20 — без надёжного совпадения.
- 3407 датированных участков/сквозных сегментов одного рейса, 3379 совпадают с тарифами.
  Это не число самолётов и не количество свободных мест.
- Пять вариантов «при необходимости» без дат исключены. В строке Ми-8 АД51
  Марково — Чуванское — Ламутское — Марково заявлено 14 рейсов, перечислено 13 дат:
  строка сохранена с флагом, но не используется автоматически.

Для ставок сохранены документ, страница, строка, НДС и период действия.
Для расписаний — исходная строка, месяцы/дни, сезонные часы и местное время.
JSON находится в `data_sources/chukotavia/dataset.json`, исходники — в игнорируемом
`data/chukotavia/`. Сервер считает по JSON без интернета, OCR и lxml.

## Формулы и ограничения

1. Тариф выбирается на местную дату планового вылета, а не готовности груза.
   Старые ставки: `[01.01.2026, 01.11.2026)`, новые — с 01.11.2026.
   Рейсы за 2027 год не достраиваются; конец действия новой ставки не опубликован.
2. Объёмный вес: `Wv = Vм³ × 1 000 000 / 6000`. Вес с упаковкой:
   `Wтариф = max(Wфакт, Wv)`, стоимость компонента `C = Wтариф × ставка`.
   Коэффициент 167 другого поставщика не используется. Деньги округляются до копеек;
   правило округления оплачиваемого веса и минимальный сбор неизвестны.
3. Ставки с НДС и без НДС сохранены отдельно, 22% взяты из документов перевозчика.
4. Время нормализовано с `+12:00`, сезонные часы привязаны к своим месяцам.
   Промежуточные посадки одного рейса сохраняются в `via`. На сквозном участке
   используется тариф между его концами, а не сумма соседних ставок.
   Пересадки между разными рейсами автоматически не создаются.
5. Разовые, регулярные и явные даты, до 64 отправок, несколько грузовых позиций.
   Название груза — свободный ввод; совместная перевозка разных грузов не подтверждается.
6. Опасные, температурные и тяжеловесные грузы не оцениваются как обычные.
   Граница 80 кг неоднозначна в двух разделах правил: на 80 кг требуется согласование.
   Пределы 200/2000 кг зависят от механизации грузового самолёта и не являются
   универсальным допуском на пассажирский рейс или вертолёт.
7. Поправка к правилам от 23.09.2026 касается грузовой накладной. Она внесена в реестр;
   старое правило исключительно бумажных экземпляров не переносится в интерфейс.

## Что показывать пользователю

Перевозчик допускает дозагрузку в свободный тоннаж без гарантированной даты.
Неизвестны свободное место на рейсе, приём конкретного груза/габаритов, крайнее время
сдачи, время обработки и состав обязательных сборов. Поэтому:

- `transport_component_estimate_rub` — оценка только тарифной составляющей;
- `total_cost_rub=null`, `recommendation=null`;
- `booking_confirmed=false`, `deadline_confirmed=false`;
- прибытие самолёта не считается выдачей груза;
- `cargo_details_to_clarify` — недостающие свойства груза.

При передаче `scenario` все три параметра являются допущениями пользователя:
`origin_processing_hours`, `cutoff_hours`, `destination_processing_hours`.
Тогда проверяется `ready + origin_processing <= departure - cutoff`;
условная выдача — `arrival + destination_processing`.
`scenario_within_deadline` сравнивает срок от готовности до условной выдачи;
он не означает гарантию перевозчика. Без сценария значение остаётся `null`.

Две партии могут показать один плановый рейс; места на нём не резервируются.
Общая грузоподъёмность самолёта не заменяет остаток свободного тоннажа.

## Искандеру и Даше

Все методы требуют прежнюю авторизацию, `credentials: "include"`.

| Метод | Назначение |
|---|---|
| `GET /network/aviation/options` | Маршруты, покрытие, источники и ограничения |
| `POST /network/aviation/calculations` | Авиационный расчёт |
| `POST /calculations` с `engine: "chukotavia"` | Тот же расчёт через общий API |

`/network/options` содержит ссылку `aviation_provider` на новые методы.
Примеры: [запрос](examples/chukotavia-request.json), [ответ](examples/chukotavia-response.json).
`origin`, `destination`, `via` — пункты из справочника; `cargoes[].name` — свободный ввод.
Обязательны вес в тоннах, объём в м³ и упаковка. До 8 плановых вариантов на каждую
готовность; это ограниченный список, а не глобальная оптимизация.
Общий предел — 30 расчётов в минуту.

Без HTTP, из корня репозитория:

```sh
.venv/bin/python -m backend.run_aviation
```

В Swagger открыть `/network/aviation/calculations` и вставить запрос из примера.
Для появления изменений в работающем приложении нужно перезапустить бэкенд.

## Общий мультимодальный граф

Адаптер подключён к общему API расчётов. Синтетические услуги старого каталога не
подменяются реальными городами. Наблюдения не превращаются в подтверждённые рёбра:
для этого нужны допуск груза, ёмкость, ограничения мест и время обработки.
Авиа Чукотки и море FESCO не склеиваются только по совпадению названия города.
