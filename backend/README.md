# Бэкенд: запуск и документы команды

Все команды выполняются из корня репозитория. Python 3.9+; контейнер использует 3.12.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app.main:app --reload
```

Swagger: `http://localhost:8000/docs`. Настройки читаются из `backend/.env`;
переменные окружения имеют приоритет. Секреты и локальные базы исключены из Git.

## Основной API для нового фронта

- `GET /network/russia/options` — поиск населённых пунктов и покрытие данных.
- `GET /network/russia/hubs?settlement=Москва` — привязанные хабы.
- `POST /network/russia/calculations` — расчёт цепочек, `engine: "russia"`.
- `GET /network/pipeline/options` — опубликованные трубопроводные компоненты.

Расчёты и прогноз доступны гостям. Браузер передаёт
`credentials: "include"` для истории аккаунта. Общий `/calculations` тоже принимает `engine: "russia"`.
Пример запроса: [russia-request.json](examples/russia-request.json).
Готовая обёртка: [russia-client.js](examples/russia-client.js).

Проверка расчёта без HTTP:

```bash
python -m backend.run_russia backend/examples/russia-request.json
```

## Прогноз грузопотока

`GET /network/forecast/options` возвращает доступные направления и диапазон лет.
В `GET /network/forecast` передаются `route_id`, `start_year` и `end_year`.
Обе границы включаются в прогноз. Допустимы годы с 2026 по 2100.

Параметр `granularity` задаёт детализацию. Значение `year` используется по умолчанию.
Можно выбрать `quarter` или `month`. Ответ содержит общий объём в тоннах
и ряд `periods`. Кварталы и годы суммируются из одного месячного прогноза.

Пример запроса для Swagger
`GET /network/forecast?route_id=<id>&start_year=2027&end_year=2030&granularity=quarter`.
В наборе 12 опорных коридоров из снимка «Точно». Конечные точки представлены
во всех восьми федеральных округах. Покрытие считается по конечным точкам.
Расстояния и расчётное время авто и ж/д взяты из снимка связности.
Месячные объёмы одного условного грузоотправителя синтетические.
Коммерческая доступность услуг и реальные грузопотоки этой проверкой не подтверждаются.

Для воспроизведения из корня репозитория:

```bash
benchmark_output=$(mktemp -d)
python3 a1-pilot/build_route_benchmark.py --connectivity backend/data_sources/russia/connectivity.json --output "$benchmark_output/dataset"
PYTHONPATH=. python3 a1-pilot/forecast_routes.py --year 2030 --output "$benchmark_output"
PYTHONPATH=. python3 a1-pilot/forecast_routes.py --year 2035 --output "$benchmark_output"
```

Сравните с `backend/data_sources/a1_forecast/route-benchmark-v2` и отчётами в `a1-pilot`.
Прогноз на 2025 год фиксируется до чтения отложенных объёмов.
Для прогноза с 2026 года модель переобучается на истории 2021–2025 годов.


## Гостевой режим и история аккаунта

Гость может рассчитать перевозку и получить прогноз. Для расчётов действует
лимит 30 запросов в минуту по IP гостя или по аккаунту после входа.

Гостевая история хранится в браузере. После подтверждения нового аккаунта
`POST /auth/verify-email` возвращает `account_created: true`, чтобы клиент мог
перенести гостевые записи в этот аккаунт.

- `GET /auth/history` возвращает записи текущего аккаунта.
- `POST /auth/history` принимает объект с `account_id` текущего пользователя и
  `snapshot` (поля `id`, `createdAt`, `result`, `draft`, `cargoNames`).
  Повторная отправка того же идентификатора в том же аккаунте безопасна.
- Клиент убирает перенесённые записи из гостевого хранилища после подтверждения
  их сохранения. История аккаунта доступна на другом устройстве после входа.

## Проверка двух гипотез на 12 коридорах

Из корня репозитория с установленными зависимостями бэкенда:

```bash
PYTHONPATH=. python3 a1-pilot/compare_corridors.py --year 2030
PYTHONPATH=. python3 a1-pilot/compare_corridors.py --year 2100
```

Можно выбрать любой год с 2026 по 2100. При нулевом объёме отправок нет,
а годовой договорной минимум продолжает начисляться. Стоимость за тонну
при нулевом объёме возвращается как `null`.

Отчёт `a1-pilot/corridor-comparison-<год>.json` сравнивает разовый автозаказ,
договорные авторейсы и «авто → ж/д → авто» на одинаковом месячном прогнозе.
На каждый месяц приходится восемь равномерно распределённых дат готовности.
Остатки между месяцами не объединяются. Договорный минимум начисляется один
раз за каждую ISO-неделю года. Экономию засчитываем, если обе схемы доставляют
весь объём в срок и стоимость гипотезы ниже стоимости разовых автозаказов.

Расстояния и расчётные часы берём из снимка «Точно». В формулах ниже отношение
всегда считается к соответствующему виду транспорта на направлении Москва → Кемерово.

- Разовое авто за машину = 260 000 ₽ × (0,10 + 0,90 × отношение расстояний).
  Договорной тариф = разовый тариф × 230/260 с минимумом два оплачиваемых
  рейса в неделю. Срок авто = 6 ч + 114 ч × отношение расчётного времени.
- Ж/д за расчётную единицу 40 т = 11,20 ₽/кг × 40 000 кг × отношение расстояний.
  Опубликованная ставка для Кемерова взята за ориентир. Оплата целой единицы
  и масштабирование ставки являются допущениями.
- Перед отправкой по ж/д закладываем 24 часа. После отправки закладываем
  12 ч + 240 ч × отношение расчётного времени. Накопление партий добавляется
  по их фактическим датам готовности в сценарии. Подвоз, развоз, терминал,
  хранение и лимиты берём из условного кемеровского каталога.
- Основной срок 14 дней. Отдельно меняем срок до 7 и 18 дней, скидку до 5% и
  20%, ж/д ставку на ±20% и объём в 0,5 и 2 раза. Цены фиксированы, без индексации.
  Итоги показывают зависимость от параметров сценария. Для коммерческого
  расчёта нужны ставки, расписания и условия обслуживания выбранных терминалов.
