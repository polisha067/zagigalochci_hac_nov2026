# Пробная часть бэкенда

Python 3.9+. Все команды ниже — из корня репозитория.

## Вход и регистрация для фронтенда

Добавлен HTTP-сервер FastAPI: регистрация, вход, текущий пользователь и выход.
Установка, запуск, примеры JSON и JavaScript: **[AUTH.md](AUTH.md)**.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
python -m uvicorn backend.app.main:app --reload
```

Документация API после запуска: `http://localhost:8000/docs`.
Для отдельного расчётного примера ниже дополнительные библиотеки не нужны.

## Запуск

```bash
python3 backend/run_demo.py
```

В Windows вместо `python3` можно использовать `py`.

Программа читает параметры из `examples/request.json`, условные тарифы из
`examples/dataset.json` и печатает результат JSON. Это основа расчётного модуля,
Он работает независимо от HTTP-сервера авторизации; API расчётов и подключение ИИ пока не реализованы.

Другой запрос:

```bash
python3 backend/run_demo.py --request backend/examples/request.json
```

## Первое упражнение — 20 минут

1. Запусти пример и найди `total_volume_tonnes`, `schemes`, `recommendation`.
2. Измени `batch_tonnes` в `examples/request.json` с 10 на 20 и перезапусти.
3. Измени вес на 21 и перезапусти. Проверь число рейсов.
4. Верни исходный вес 10 тонн.

| Вес партии | Объём за 4 недели | Физические рейсы | Разовые заказы | Договор |
|---|---:|---:|---:|---:|
| 10 т | 80 т | 8 | 240 000 ₽ | 208 000 ₽ |
| 20 т | 160 т | 8 | 240 000 ₽ | 208 000 ₽ |
| 21 т | 168 т | 16 | 480 000 ₽ | 416 000 ₽ |

Расчёт для 10 тонн: 10 × 2 отправки × 4 недели = 80 тонн.
Каждая отправка требует отдельную машину. Вместимость — 20 тонн.
При 21 тонне нужны две машины одновременно. Их доступность — допущение.

## Файлы и формат

- `calculator.py`: функция `compare_delivery(request, dataset)`.
- `run_demo.py`: запуск из терминала.
- `examples/request.json`: направление, груз, вес партии (тонны), отправки в неделю,
  горизонт (целые недели), максимальный срок (дни от готовности до доставки).
- `examples/dataset.json`: ставки (рубли за рейс), вместимость (тонны),
  срок (дни), договорный минимум оплачиваемых рейсов за неделю и источник.
- `test_calculator.py`: проверка ручных примеров и важных ограничений.

Результат содержит объём по неделям, число отправок, затраты за период и за тонну,
фактические и оплачиваемые рейсы, сроки, экономию относительно базы и рекомендацию.
`savings_vs_base_rub` положительно при экономии, отрицательно при удорожании.
Статусы: `feasible`, `infeasible`, `insufficient_data`.
Рекомендация выбирается только среди рассчитанных схем с допустимым сроком;
если их нет, возвращается `null`. Отсутствующий тариф не считается нулём.

## Ограничения

Москва — Брянск и мука — пример, не выбранный реальный пилот.
Все тарифы вымышленные (`synthetic`), источник и дата подготовки указаны в наборе.
Ставки предполагаются сопоставимыми по налогам и включающими всю автодоставку.
Объём рассчитан по плану, без роста и истории: это сценарная оценка, не статистический прогноз.
Частота и горизонт — положительные целые числа. Календарные даты, отправки раз в две
недели и объединение партий пока не поддерживаются.
Ж/д схема возвращает `insufficient_data`: расчёт цепочки ещё не реализован.
Условия договора с минимумом тоннажа потребуют отдельной модели.
Следующие этапы: согласовать поля с командой, получить реальные данные, добавить
проверяемый прогноз по истории, полную ж/д цепочку и HTTP API.
