# Ограничения и проверки расчёта 0.2

Замечания Полины реализованы в пределах явно заданной модели.
Основные тесты: `test_transport.py`, `test_calculation_api.py`.

| Случай | Поведение |
|---|---|
| Произвольный срок, включая доли дня | Положительное число часов; 0.5 часа допустимо |
| Срок равен фактическому | Допускается |
| Срок слишком мал для всех схем | HTTP 200, схемы недопустимы, recommendation = null |
| Разовая перевозка | Ровно одна отправка независимо от регулярной модели |
| Раз в две недели | count=1, every=2, unit=week |
| Несколько раз в день/неделю/месяц | Равномерное расписание; для точных дат — explicit |
| Неполный период | Считаются реальные события, не дробное число рейсов |
| Готовность на правой границе | Не включается в regular |
| 31 января и короткий февраль | Календарный февраль, затем возврат к исходному дню марта |
| Дата без пояса, дубликат момента | 422 |
| Число вместо даты | 422 |
| Нули/отрицательные числа/NaN/бесконечность/boolean вместо веса | 422 |
| Строка «2 дня» вместо числа часов | 422 |
| Неизвестное поле | 422, включая неподдерживаемые требования |
| Пустые грузы, маршрут или даты | 422 |
| Неверные индексы погрузки/выгрузки, повтор id | 422 |
| Совпадающие соседние города | 422: адресная внутригородская модель пока не поддерживается |
| Город есть в списке, но нет тарифа на плечо | insufficient_data, без подстановки прямого маршрута |
| Несколько грузов с разными местами погрузки/выгрузки | Загрузка считается по участкам |
| Пустой участок маршрута | Фиксированный парк проходит и оплачивает его |
| Промежуточная остановка | Время и отдельная плата за остановку плюс тарифы всех плеч |
| Большая масса или большой объём | Округление машин вверх; ограничивающим может быть любой показатель |
| Только масса известна | Нужен явный mass_only; предупреждение о непроверенном объёме |
| Неделимая позиция больше машины | infeasible |
| Несколько машин и неделимые позиции | insufficient_data: нужен план размещения |
| Несовместимые одновременно загруженные грузы | infeasible для модели совместной партии |
| Неизвестная совместимость/свойства | insufficient_data |
| Последовательная смена разных профилей груза | insufficient_data без плана очистки |
| Машин/ж/д единиц известно 0 | infeasible |
| Нет подтверждения мощности | insufficient_data |
| Ставка отсутствует или некорректна | insufficient_data, не нулевая стоимость |
| Действительная бесплатная ставка 0 | Считается явно; процент экономии при нулевой базе не делится на 0 |
| Тариф просрочен или нет источника | insufficient_data |
| Договор дешевле за рейс, но есть минимум | Оплачиваются минимальные рейсы за каждую затронутую неделю |
| Неделя без отправок внутри договора | Всё равно учитывается минимум |
| Неполная договорная неделя | Полный минимум согласно данному типу договора |
| Подача/погрузка переносит выезд в новую неделю | Учитывается дополнительная неделя договора |
| Ж/д партия ещё не накоплена | Ожидание входит в срок самой ранней отправки |
| Малый остаток в конце | Не теряется; разбиение отклоняется либо остаток входит в допустимую большую группу |
| Накопление и обработка пропускают поезд | Берётся следующее отправление из расписания |
| Несколько групп попадают на одно отправление | Потребность в ж/д единицах и развозе суммируется |
| Хранение партий разной готовности | По тонно-суткам каждой исходной отправки, а не всем по максимальному ожиданию |
| Ж/д с промежуточными погрузками | insufficient_data: модель и тариф цепочки пока отсутствуют |
| Деньги | Decimal, округление компонентов до копеек, сумма компонентов равна итогу |
| Клиент пытается задать ставку | 422: тарифы берутся на сервере |
| Нет входа/сессия истекла | 401 для HTTP-расчёта |
| Больше 30 расчётов в минуту | 429 и Retry-After |
| Слишком большой план | 422 до дорогого перебора вариантов |

## Границы модели, которые должны быть видны пользователю

1. Пока это сценарная оценка без статистического прогноза и роста по истории.
2. Одинаковый состав повторяется во всех отправках. Готовность всех позиций каждой
   отправки общая. Другой состав/время по каждой дате потребует расширения контракта.
3. Оптимизация геометрии упаковки, раздельных машин для несовместимых грузов,
   объединения автозаказов и динамического парка по участкам не реализована.
4. Нет оптимизации оборота общего парка между рейсами, окон приёма, выходных и возврата
   тары. Доступность на одну отправку не означает доказанной достаточности общего парка.
5. Для ж/д перебираются равные последовательные группы и остаток. Произвольное
   разбиение и перенос на следующий поезд ради освобождения мощности не оптимизируются.
6. Температурные, упаковочные, опасные и другие специальные требования должны быть
   подтверждены для конкретной услуги в данных; текущий демо-набор описывает только сухие пищевые грузы.
7. В каталоге пока только синтетические возможности и тарифы. Даже feasible — это
   вывод при заданных условиях, а не подтверждённая заявка перевозчику.

Новые пожелания команды сначала добавляем в контракт/матрицу и тесты, затем в экран.
Нельзя принимать дополнительный параметр, молча игнорируя его при расчёте.
