# Аудит 31 предоставленного источника

Проверка: **8 ноября 2026 года**. В исходном списке 31 запись и 25 различных URL. Повторение одного URL под разными задачами не создаёт независимые наборы данных. Машиночитаемый реестр: [registry.json](registry.json).

Проверка страницы не означает проверку всех файлов сайта. «Недоступен» означает неудачное получение в этой сессии (тайм-аут/403 и т.п.), а не отсутствие данных. Описания команды сохранены отдельно от результатов проверки. Ниже приведены именно результаты проверки, без принятия исходных описаний на веру.

Статусы записей: проверен файл — 9, только оболочка страницы — 1, проверена страница — 7, недоступен при проверке — 14.

Набор связности опубликован «Точно» с лицензией CC BY 4.0. При использовании сохранять атрибуцию и версию. Условия других выгрузок проверять отдельно. Geofabrik/OSM требует соблюдения ODbL; нельзя считать весь список одинаково лицензированным.

## Что запросить у организаторов / перевозчиков

Для каждого пилотного маршрута нужны:

- История именно нужного грузового потока: дата, отправитель/получатель или направление, тип груза, тонны, при возможности м³ и частота. Агрегаты региона идут отдельно.
- Идентификаторы конкретных терминалов, координаты, принимаемые виды/упаковки/температура, часы работы и сроки действия сведений.
- Направленные грузовые услуги между терминалами: виды транспорта, грузовые ограничения, расписание, cutoff, время движения, минимальная партия, полезная масса/объём, доступные единицы/производительность и время оборота.
- Явные стыковки в хабах: какие услуги можно соединить, время и цена обработки, линии обработки, хранение и подтверждённый приём груза.
- Тарифы: дата и период действия, валюта, единица, минимум/фиксированные сборы, налоговый состав, включённые услуги. Для авиа — коэффициент объёмного веса; для W/M — правило расчётной тонны.
- По видам: колея и допуск терминалов для ж/д; осадка/навигация/ледовый допуск/мосты для воды; габариты и масса места для авиа; продукт/подключения/производительность для трубопровода.
- Условия договора для гипотезы регулярных рейсов: действительная ставка, минимальные оплачиваемые рейсы/объём, период расчёта. Скидку по сравнению с разовым заказом не следует придумывать.
- Разрешение на публикацию данных и использование синтетики в проверке гипотез.

До получения данных допускается только явно обозначенная сценарная оценка «при заданных условиях». Для защиты нужен один воспроизводимый пилот с первичными подтверждениями каждой услуги и стыковки; охват всех российских направлений не следует обещать.

## Воспроизводимый импорт

Из корня репозитория после скачивания нужного архива:

```bash
python -m backend.import_sources connectivity /path/to/connectivity.zip
python -m backend.import_sources regional /path/to/transport.zip
```

Проверенные ссылки на версии архивов:

- [Связность, версия 20260629](https://storage.yandexcloud.net/tochno-st-catalog/Geo/data_intercity_connectivity_162_v20260629/data_intercity_connectivity_162_v20260629_csv.zip)
- [Транспорт регионов, версия 20260313](https://storage.yandexcloud.net/tochno-st-catalog/Rosstat/data_regions_collection_102_v20260313/data_transport_102_v20260313.zip)

Импортёр не распаковывает пути ZIP, пропускает метаданные macOS, ожидает один CSV UTF-8 с разделителем `;`, проверяет схему, числа, координаты и дубли, выполняет замену одного источника транзакционно. Ограничения: 100 MB входного файла/распакованного CSV, 200 000 строк. При изменении структуры исходного файла импорт останавливается, а не угадывает единицы или колонки. Повторный успешный импорт одного источника заменяет его наблюдения; ошибка откатывает замену.

Метод `GET /network/options` показывает состояние локальной БД наблюдений отдельно от каталога грузовых услуг. Чтобы работать на другой машине, данные нужно импортировать там либо передавать согласованный снимок отдельно; обычный `git pull` локальную SQLite не переносит.
