# Контракт транспортного ассистента

Контракт рассчитан на один груз между двумя пунктами, разовое и регулярное
расписание. Сценарии с остановками и несколькими грузами доступны через полную
форму расчёта. Её контракт описан в [CALCULATIONS.md](CALCULATIONS.md).

## HTTP

`POST /assistant/chat` доступен после входа подтверждённого пользователя.
Из браузера передавайте JSON и `credentials: "include"`. Ручка использует
текущие ограничения по Origin и авторизации. Ответы защищены от кеширования.
Контракт доступен в Swagger по адресу `http://localhost:8000/docs`.

```json
{
  "message": "Нужно возить по 10 тонн муки из Москвы в Брянск",
  "draft": null
}
```

В `message` допустимо до 2000 символов после удаления внешних пробелов. В первом
запросе `draft` можно опустить. Для продолжения передавайте последний полученный
`draft` без преобразования полей. Для нового расчёта передайте `null`.

Черновик содержит `origin`, `destination`, `cargo_type`, `weight_tonnes`,
`volume_m3`, `splittable`, `schedule`, `max_delivery_hours` и
`capacity_basis`. До уточнения значение может отсутствовать или быть `null`.
У `schedule` допустимы режимы `once` с `ready_at` и `regular` с
`start_at`, `end_at` и `frequency`. Даты передаются с часовым поясом.
Параметры периода и единиц совпадают с контрактом расчёта.

## Ответ и обработка ошибок

Ответ всегда содержит `kind`, `reply`, `draft`, `missing_fields`,
`calculation` и `sources`.

| `kind` | Поведение фронта |
|---|---|
| `clarification` | Показать `reply`, сохранить `draft`. В `missing_fields` перечислены поля, например `schedule.frequency`. |
| `calculation` | Показать `reply` и обновить таблицу и график из `calculation`. Это тот же контракт, что у `POST /calculations`. |
| `information` | Показать `reply` и документы из `sources`, сохранить черновик и предыдущий расчёт. |

Ссылки на расчётные данные берутся из `calculation.sources`. У справочных
источников чата есть `title`, `url` или `path`, а при наличии `section`
и `date`. В качестве внешней ссылки используйте поле `url`. Поле `path`
содержит относительный путь к документу проекта.

Ошибки возвращаются в формате `{"error":{"code":"…","message":"…","fields":[]}}`.
Счётчик запусков расчёта общий с формой. При превышении лимита действует
`429` с `Retry-After`. Недоступность обработчика сообщений и таймаут
возвращают `503 assistant_unavailable`. Некорректное действие обработчика
возвращает `502 assistant_invalid_response`. При временной недоступности
ассистента пользователю доступна форма расчёта.

## Граница интеграции модели

Сервис принимает обработчик сообщений через `create_app(assistant_planner=…)`.
Обработчик получает `ChatRequest` и возвращает `DeliveryTurn` с обновлённым
черновиком или `InformationTurn` с текстом и источниками. Сервис вызывает
обработчик один раз за запрос. Полный черновик собирается в существующий
`CalculationRequest`, затем выполняется тот же расчёт, что у формы. Сервер
выбирает каталог и задаёт идентификатор груза.

В блоках 1–3 проверка выполняется с подставным обработчиком в тестах.
Обычный запуск приложения возвращает для авторизованного чата
`503 assistant_unavailable` до подключения Qwen в блоке 4.
Поиск документов подключается в блоке 5.

## Контрольный расчёт

Из корня репозитория в Python-окружении с установленными зависимостями:

```powershell
python -m backend.run_calculation
python -m unittest discover -s backend -p "test_*.py"
```

Контрольная версия расчётного ядра — `cc2b302`, каталог — `synthetic-pilot-v2`.
Запрос [Москва → Брянск](examples/calculation-request.json) даёт 8 отправок
и 80 т в синтетическом сценарии. При лимите 48 ч результат рекомендует
договорное авто за 208 000 ₽. При лимите 168 ч рекомендует ж/д схему
за 140 000 ₽ со сроком 156 ч. В тесте чата результат сравнивается с формой
на одинаковых условиях.

Проверка блоков 1–3 на Windows прошла все 95 тестов бэкенда, включая 11
тестов ассистента. В существующем тесте миграции SQLite временное
соединение закрывается перед удалением файла базы.
