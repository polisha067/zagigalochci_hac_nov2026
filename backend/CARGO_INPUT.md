# Свободный ввод груза и требования Полины

Пользователь **сам пишет название груза**. Список известных наименований — только необязательные подсказки; выбор из закрытого списка не требуется. Фронт не должен заранее подставлять муку или первый товар списка.

Изменения относятся к бэкенду. Сам экран делает Искандер. Контракт сетевого ответа 0.3 расширен полями, версия HTTP-приложения — 0.5.0.

## Для Искандера

1. Заменить обязательный список «Выберите груз» полем «Что перевозим?», например «Пшеничная мука». Хранить введённую строку в `cargoes[].name`.
2. Подсказки можно брать из `/network/options → cargo_types`: `name` и `aliases`. Нажатие на подсказку необязательно. Справочные id не должны быть условием заполнения формы.
3. Для каждой позиции задаются масса, упаковка, возможность разделения партии, объём при объёмной проверке и необходимые ограничения. `+ Добавить груз` сохраняется.
4. Отправлять запрос в `POST /network/calculations` с `engine: "network"`. Пример: [examples/network-free-cargo-request.json](examples/network-free-cargo-request.json).
5. Если `input_status="needs_clarification"`, показать `clarifications[].message` рядом с позицией по `cargo_id`; не рисовать рекомендацию и цену. После ответа пользователя обновить ту же позицию и повторить запрос.
6. Если `input_status="ready"`, работать с кандидатами как прежде. Это означает достаточность описания входа, а не подтверждённую доступность всех перевозчиков.
7. `insufficient_data` внутри кандидата может означать, что груз описан, но оператор ещё не подтвердил его приём/совместимость. Это отличается от отсутствующего поля формы.

`/network/options → cargo_input` сообщает режим `free_text`, необязательность подсказок, упаковки и известные профили условий обращения. Профиль — характеристика обработки груза, не выбор его названия. Новое название разрешено и при отсутствии подходящего профиля/перевозчика; результат тогда честно укажет, каких данных не хватает.

## Как работает распознавание

Точное сопоставление по известному имени или явно записанному синониму, с приведением регистра, пробелов, Unicode и «ё/е». Например, «МУКА» и «пшеничная мука» распознаются как известная мука. Подстроки и сходство написания не используются: «мука с опасной добавкой» не получает свойства обычной муки.

Узнанное название использует свойства и источники существующего типа. `cargo_type` оставлен для старых клиентов; если одновременно переданы имя и id, они обязаны согласовываться. Неизвестное имя вместе с id муки не обходит проверку.

Если имя неоднозначно или свойства противоречат известному описанию, сервер возвращает уточнение. ИИ может помочь сформулировать вопрос, но не должен выдавать предположение за подтверждённое свойство.

## Новый груз

Сервер принимает неизвестное название без добавления товара в глобальный каталог. Если не хватает данных, возвращает вопросы. Для расчёта по пользовательскому описанию нужны:

```json
{
  "id": "cargo-1",
  "name": "Новая пищевая крупа",
  "weight_tonnes": 10,
  "volume_m3": 20,
  "packaging": "bags",
  "splittable": true,
  "properties": {
    "phase": "solid",
    "hazardous": false,
    "handling_profile": "dry_food",
    "temperature_control_required": false
  }
}
```

Это пример **заявленных пользователем условий**, не автоматический вывод из слова «крупа». Свойства получают статус `assumption`. Если температурный режим нужен, требуется `required_temperature_c`, например `[2,8]`. Указанные требования пересекаются с остальными температурными ограничениями и не ослабляют известные требования типа груза.

Проверки:

- `properties` не содержит пользовательского `evidence` или способа объявить сведения фактом. `verified_only` не допускает расчёт на неподтверждённых свойствах.
- У хаба, перевозочной услуги и перегрузки должен быть явный допуск конкретного типа либо профиля `cargo_profiles`. Допуск мешков сам по себе не означает допуск любого содержимого.
- В учебном каталоге профиль `dry_food` явно разрешён для соответствующих объектов. Это синтетический пример, не подтверждённый список услуг по России.
- Если допуск отсутствует, возвращается `cargo_admission_unconfirmed`, итоговой цены нет.
- Трубопровод по-прежнему требует конкретный допущенный продукт. Жидкое состояние само по себе не разрешает прокачку.
- Разные новые грузы не считаются совместимыми только потому, что у них один профиль. При неизвестной совместимости требуется подтверждение; раздельная оптимизация перевозки пока не реализована.
- Опасность, температура, размеры, масса места и упаковка проверяются обычными правилами ядра. Полного нормативного допуска опасных грузов эта версия не выдаёт.
- Пользовательские описания живут только внутри запроса. Они не меняют общий каталог и не становятся свойствами грузов других пользователей.

Примеры: [новое имя без свойств](examples/network-unknown-cargo-request.json), [новое имя с заявленными свойствами](examples/network-declared-cargo-request.json). Во втором примере стоимость допустима только при учебном профиле приёма и синтетических тарифах.

## Частота без ограничения «в неделю»

Формат регулярности — **count отправок каждые every unit**. Доступны `minute`, `hour`, `day`, `week`, `month`.

```json
{"count":2,"every":3,"unit":"day"}
```

Это две отправки каждые три дня. Полтора часа задаются как `every:90, unit:"minute"`. Для точных произвольных дат — `schedule.mode="explicit"`; для одной перевозки — `once`. Технические пределы количества отправок остаются действующими. Даты регулярных готовностей распределяются равномерно внутри интервала; не следует обещать заданные дни недели без `explicit`.

## Несколько остановок

`via_hub_ids` принимает до 10 обязательных промежуточных хабов в порядке посещения, в пределах общего лимита 12 этапов. Для каждой позиции `pickup_hub_id` / `delivery_hub_id` указывают её погрузку и выгрузку. Остановка без изменения груза и подтверждённая перегрузка между услугами — разные вещи. Последняя требует Transfer в каталоге.

Старый `POST /calculations` без `engine` тоже принимает `name` вместо обязательного `cargo_type`: известные имена работают, неизвестные возвращают уточнение и отсутствие рекомендации. Подробные пользовательские свойства и сетевые цепочки доступны в новом сетевом контракте. Фронту рекомендуется новый метод.

## Что не нужно выводить в форме

Таблицы АСОП, полную выгрузку Росморпорта и сценарии стратегии пользователь не выбирает. Это внутренние источники. На экране нужны параметры груза, результаты и относящиеся к ним источники/допущения.
