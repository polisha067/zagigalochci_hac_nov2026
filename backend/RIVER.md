# Речной сценарий Красноярск ↔ Дудинка

Подключён к существующему сетевому расчётному ядру, а не к отдельному калькулятору.
`network_id: "river-krasnoyarsk-dudinka-scenario-v1"`.
Сеть содержит два сценарных узла и четыре услуги: 20/40 футов в каждом направлении.
«Выполнимо» и рекомендация означают результат при заданных сценарных условиях,
а не подтверждённый рейс, заказ или гарантированный срок перевозчика.

## Подтверждённая часть

Источник: [прайс-лист Трасса-Экспресс 2026](https://trassa-express.com/PRAIS-LIST/),
проверен 08.11.2026. Контрольная сумма страницы сохранена в `network.json`.

| Компонент | 20 футов | 40 футов |
|---|---:|---:|
| Речная перевозка Красноярск ↔ Дудинка, без ПРР | 133 000 ₽ | 247 000 ₽ |
| Обработка гружёного контейнера в Красноярске | 12 000 ₽ | 20 000 ₽ |
| Обработка гружёного контейнера в Дудинке, причал совхоз «Полярный» | 20 000 ₽ | 30 000 ₽ |
| Хранение в Красноярске, контейнер/сутки | 300 ₽ | 500 ₽ |
| Хранение в Дудинке, контейнер/сутки | 400 ₽ | 600 ₽ |

Опубликованные суммы включают НДС 5%. В обратном направлении портовые сборы
меняются местами; речной тариф на странице одинаков для обоих направлений.
Не смешивать причал «Полярный» с тарифами ЗТФ другого терминала Дудинки.
Строка «услуги грузчиков от 6000 до 8000» не добавляется поверх обработки 12000:
неизвестно, входит ли она в ту же операцию. В сценарии она отдельно не применяется.

## Синтетическое заполнение пробелов

Все значения ниже — настройки сценария, не сведения перевозчика.
Они структурированно сохранены в источнике `river-gap-scenario-v1`, включая причину.

| Параметр | Значение |
|---|---|
| Навигация | с 1 июня до 1 октября 2026; конец исключается |
| Отправления | четверг: Красноярск 10:00, Дудинка 14:00, UTC+7 |
| Переход вниз / вверх | 144 / 192 часа |
| Крайний приём | за 24 часа до выезда, после завершения подготовки |
| Полезная загрузка 20 / 40 футов | 18 / 24 т, полезный объём 28 / 58 м³ |
| Тара 20 / 40 футов | 2,3 / 3,8 т |
| Ограничение брутто 20 / 40 футов | 24 / 30,48 т |
| Размер отдельного места | до 2×2×2 м, до 2 т; поворот разрешён |
| Условный лимит одного отправления | 8 контейнеров каждой размерной альтернативы |
| Обработка в каждом конце | 2 часа + масса партии / 10 т/час; 2 линии |
| Вместимость хранения узла | 500 т / 1500 м³, до 240 часов |
| Осадка судна / предел | 2 / 2,5 м; летний сценарий без ледового требования |
| Приём груза | сухой неопасный твёрдый груз, bags/boxes, без температурного режима |

Красноярская площадка условная: прайс не подтверждает конкретную рабочую технологию
и доступность причала. В Дудинке название причала взято из прайса, его доступность,
ресурсы и окна работы остаются сценарными. Координаты не выдумываются.
Временные окна обоих узлов, услуги и прибытия должны укладываться в навигацию.
Нельзя продлевать её на зиму или автоматически повторять в 2027 году.

Контейнеры собственные, груз уже затарен отправителем. Аренда, затарка, упаковка,
подвоз и вывоз не входят в моделируемый речной участок. Это условие плана, не
утверждение о бесплатных услугах оператора. Для полного маршрута нужны отдельные плечи.

## Формулы

Для контейнера данного размера:

```text
q = min(полезная загрузка, допустимое брутто − тара)
n = max(ceil(масса / q), ceil(объём / полезный объём))
Cперевозки = n × речной тариф
Cобработки = n × (тариф порта отправления + тариф порта назначения)
готовность_после_обработки = готовность + 2 ч + масса / 10 т/ч
выезд = первое сценарное отправление после готовности_после_обработки + 24 ч
прибытие = выезд + время перехода
выдача = прибытие + 2 ч + масса / 10 т/ч
срок = выдача − исходная готовность
```

Неделимый груз не дробится автоматически. Проверяются места, масса, объём,
осадка, остаток сценарных ресурсов и срок каждой исходной позиции.
Слишком большая партия не выдаётся за доставленную частично.

Хранение считается за контейнеро-сутки, а не за тонно-часы:

```text
D = ceil(max(0, часы хранения − бесплатные часы) / 24)
Cхранения = n × D × ставка за контейнеро-сутки
Cучастка = Cперевозки + Cобработки + Cхранения
```

Округление начатых 24 часов — допущение. В Красноярске принят free=0;
в Дудинке free=72 часа из строки прайса «хранение более 3 суток».
Точное календарное правило тарификации и отсчёт срока не подтверждены.
Для объединённых партий консервативно считаем все контейнеры с самой ранней
готовности соответствующей загрузки. Эти правила помечены как assumption,
хотя числовые суточные ставки опубликованы.

Деньги округляются по компонентам до копеек; при расчёте без НДС компоненты
делятся на 1.05. ПРР начисляются на каждый контейнер, повторно в физической
операции узла не начисляются. Нулевые строки `pickup_handling`/`delivery_handling`
означают, что деньги уже вынесены в именованные портовые компоненты услуги.
Рекомендация сравнивает только варианты данного сценария.

## Как использовать

1. `GET /network/options?network_id=river-krasnoyarsk-dudinka-scenario-v1`.
2. `POST /network/calculations` или `POST /calculations` с `engine: "network"`
   и указанным `network_id`. Авторизация прежняя, `credentials: "include"`.
3. [Пример запроса](examples/river-request.json), [пример ответа](examples/river-response.json).

Без HTTP, из корня репозитория:

```sh
.venv/bin/python -m backend.run_network --network backend/data_sources/river/network.json --request backend/examples/river-request.json
```

В примере 10 т / 20 м³, готовность 08.06.2026 в 08:00 UTC+7:
20-футовый контейнер — 166200 ₽ = 133000 + 12000 + 20000 + 1200 хранения.
40-футовый — 299000 ₽. Это модельная сумма только речного участка при перечисленных
допущениях, а не предложение перевозчика. Тарифы и все сценарные настройки
возвращаются в `sources`, `coverage`, `evidence_levels` и предупреждениях ответа.
`verified_only` не разрешает этот сценарий: на фоне реальных ставок он содержит допущения.

Снимок хранится в `data_sources/river/network.json`; генератор —
`data_sources/river/build_scenario.py`. Пересборка не скачивает сайт. Если сохранённый
исходный HTML изменился, проверка SHA-256 останавливает сборку до ревизии ставок.
Все технические пределы основного сетевого ядра сохраняются.

Для применения к работающему серверу нужен перезапуск. Фронт должен явно показывать
«Сценарная оценка»; наличие статуса `feasible` не означает реальное бронирование.
