# Формулы сетевого расчёта 0.3

> Речной сценарий Красноярск ↔ Дудинка: опубликованные компонентные тарифы + явно заданные синтетические условия. Подключение и формулы — [RIVER.md](RIVER.md).


> Авиация ЧукотАВИА: опубликованные тарифы и плановые рейсы подключены отдельным методом и к общему `/calculations` с `engine: "chukotavia"`. Формулы и ограничения — [AVIATION.md](AVIATION.md). «Аэрогруз» не используется.


Это формулы реализованного алгоритма, а не универсальные тарифы перевозчиков. Все ставки, коэффициенты, расписания и ограничения поступают из версии каталога с источниками. Учебные параметры — синтетические. Общая архитектура и границы применимости: [NETWORK.md](NETWORK.md).

## 1. Исходный объём и сохранение груза

Пусть `t_i` — момент готовности отправки, `m_j` — масса позиции в тоннах, `v_j` — объём в м³, `δ_j` — дополнительное время готовности. Экземпляр груза `(i,j)` готов в `r_ij = t_i + δ_j`.

```text
S = число моментов готовности внутри заданного периода
Q = Σ_i Σ_j m_j = S × Σ_j m_j
V = S × Σ_j v_j                 (если известны все объёмы)
Q_доставлено = Q                (обязательная проверка полного результата)
```

Для разовой перевозки `S = 1`. Для регулярной используется `[start_at, end_at)`, а не приближённое число недель/месяцев. Для явно заданных дат учитываются все заданные моменты. Позиции с промежуточной погрузкой тоже входят в общий объём, но не в загрузку ранних этапов.

В общем случае загрузка этапа `l`:

```text
M_l = Σ m_ij по позициям, погруженным до l и ещё не выгруженным
V_l = Σ v_ij по тем же позициям
```

Грузооборот, если его впоследствии считать: `Σ_l M_l × distance_l`, т·км. Его нельзя путать с объёмом Q, т; один груз на трёх этапах не превращается в три поставки. В текущем ответе отдельная метрика грузооборота не выдаётся.

## 2. Вместимость и транспортные единицы

Для каждого этапа полезная грузоподъёмность:

```text
q_mass = min(unit_tonnes, gross_limit_tonnes − tare_tonnes)
```

Если ограничение полной массы не задано, используется `unit_tonnes`. Если полная масса задана, тара обязательна. При `q_mass ≤ 0` перевозка невозможна.

```text
n_mass = ceil(M_l / q_mass)
n_volume = ceil(V_l / unit_m3)
n_l = max(1, n_mass, n_volume)
```

Объёмная проверка выполняется при `mass_and_volume` или при известных объёме и объёмной вместимости. В `mass_only` отсутствие объёма явно отражается как ограничение проверки. Для авиации объём всё равно обязателен.

```text
M_l ≥ min_batch_tonnes
n_l ≤ available_units
```

Неделимая позиция не может превышать вместимость одной единицы. Когда неделимые позиции требуют нескольких единиц, формула `ceil` сама по себе не доказывает укладку: выдаётся `load_plan_required`, требуется отдельный план. Масса и габариты максимального места проверяются отдельно; поворот разрешён только при `allow_rotation=true`.

## 3. Стоимость этапа

Сначала определяется оплачиваемое количество `x`:

| Основание тарифа | x | Единица ставки |
|---|---|---|
| `per_unit` | n_l | руб./единицу |
| `per_tonne` | M_l | руб./т |
| `per_kg` | 1000 × M_l, с правилами объёмного веса ниже | руб./кг |
| `per_tonne_km` | M_l × distance_l | руб./(т·км) |
| `weight_or_measure` | max(M_l, V_l × k_wm) | руб./расчётную тонну |
| `per_tonne_hour` | Σ m_ij × h_ij | руб./(т·ч) |

```text
C_component = round_money(max(minimum_rub, rate_rub × x) + fixed_rub)
```

Минимум применяется к переменной части; фиксированный сбор прибавляется после него. Оба относятся к одной партии/операции. Для тарифа, устроенного иначе, нужно изменить нормализацию, а не подставлять похожее число.

`round_money` — Decimal с округлением до копеек (HALF_UP). Компоненты округляются отдельно, итог равен сумме выданных компонентов. `null` не заменяется нулём.

### Авто и ж/д

Для выделенной машины/вагона с ценой за единицу: `x = n_l`. Для ставки на тонну или т·км применяются соответствующие строки таблицы. Ставка выбирается из конкретной услуги; скидка за регулярность автоматически не придумывается.

### Море и река

В зависимости от нормализованной котировки используются единица, тонна, т·км или W/M:

```text
x_wm = max(M_l, V_l × k_wm)
```

`k_wm`, т/м³, обязательно берётся из тарифа. Нельзя считать, что один м³ любого груза равен одной физической тонне. Портовая обработка и хранение добавляются только как отдельные подтверждённые компоненты. Ставка `all_in` без разложения не складывается повторно с терминальными сборами.

### Авиация

```text
W_actual_kg = 1000 × M_l
W_volume_kg = V_l × volumetric_kg_per_m3
W_chargeable_kg = max(W_actual_kg, W_volume_kg)
C_air = round_money(max(minimum_rub, rate_rub × W_chargeable_kg) + fixed_rub)
```

Коэффициент и правило берутся из тарифа. В учебном примере 200 кг/м³ — условное число, не утверждение о рынке. Реальные правила округления каждого места/ступеней тарифной сетки требуют нормализации; текущая версия считает общий объём партии.

### Трубопровод

```text
h_injection = M_l / flow_tonnes_per_hour
arrival = departure + h_injection + travel_hours
```

Это явная упрощённая модель «закачка всей партии плюс транспортная задержка». `travel_hours` должна быть определена в этих же терминах, чтобы не задвоить время. Ресурс закачки занят на `[departure, departure + h_injection)`; цена — по указанному основанию, например т·км. Продукт должен соответствовать одному `commodity_id`; смена продукта, буферные ёмкости и гидравлическая оптимизация автоматически не моделируются.

## 4. Обработка и стыковка

Для приёма, выдачи или перехода в хабе:

```text
h_handling = fixed_hours + M / tonnes_per_hour
start = первый момент ≥ ready, в котором есть свободная линия
        и вся операция входит в рабочее окно
end = start + h_handling
C_handling = цена операции по её Quote
```

На одном ресурсе одновременно не более `lanes` операций. Общий `resource_id` связывает занятость между разными отправками и операциями; противоречивые мощности одного ресурса отклоняются при загрузке каталога.

Переход допускается только при наличии однозначного Transfer для входящей и исходящей услуг, груза и упаковки. Между разными хабами нужна перевозочная услуга; одинаковое название города не создаёт бесплатного перехода.

## 5. Расписания, ожидание и сроки

Пусть `ready_l` — окончание необходимых операций, `c_l` — cutoff в часах. Нижняя граница отправления `a_l = ready_l + c_l` с учётом начала действия данных.

```text
on_demand: d_l = первый доступный момент ≥ a_l
explicit:  d_l = min {d из departures: d ≥ a_l и выполнены ограничения}
interval:  d_l = anchor + k × every_hours,
           k = max(0, ceil((a_l − anchor) / every_hours))
```

При занятых ресурсах или закрытом окне проверяются следующие реальные отправления/границы окон. Прибытие обычного вида: `a_next = d_l + travel_hours`. Для трубопровода добавляется время закачки. Приём в следующем хабе должен быть открыт на момент прибытия.

```text
T_ij = finished_delivery_ij − r_ij
D_ij = min(индивидуальный срок или общий срок,
           срок годности или общий срок)
T_ij ≤ D_ij                   для каждого исходного экземпляра
```

Время считается от готовности до окончания выдачи: ожидание накопления, cutoff, перегрузки и хранение включены. В ответе `max_delivery_hours` кандидата — фактический максимум T, а одноимённое поле запроса — ограничение.

## 6. Консолидация и хранение

Для размера группы `g` последовательно объединяются до `g` исходных отправок. Сохраняется последняя группа меньшего размера. Готовность общей партии — не раньше самого позднего груза и необходимых операций. Каждая позиция сохраняет свой первоначальный срок.

В каждом хабе:

```text
H = Σ_ij m_ij × (custody_end_ij − custody_start_ij), т·ч
C_storage = round_money(rate_rub × H)
Σ массы одновременно находящихся грузов ≤ storage_tonnes
Σ объёмов одновременно находящихся грузов ≤ storage_m3
custody_hours_ij ≤ max_storage_hours
```

Хранение в этой версии линейное, без фиксированных/минимальных сборов. Исходная точка: от готовности до отправления. Транзит: от прибытия до следующего отправления. Конечная выдача: от прибытия до конца выдачи. Совместимость проверяется и для пересекающегося складского хранения разных партий.

## 7. Общие мощности

Все интервалы полуоткрытые: `[start, end)`. Освобождение в 10:00 допускает новое занятие в 10:00.

```text
Σ amount_r(t) ≤ capacity_r       для каждого общего ресурса и момента t
```

Выделенный парк: `amount=n_l`, занятие до `arrival + turnaround_hours`. Сборная услуга: сумма масс/объёмов на конкретном отправлении; полезная масса учитывает тару. Заказная сборная услуга без явных отправлений не принимается. Трубопровод: один общий ресурс закачки. Склад и линии обработки учитываются аналогично.

Эти остатки существуют только внутри сценария; между HTTP-запросами они не резервируются.

## 8. Итог и выбор

```text
C_route = Σ C_transport + Σ C_handling + Σ C_storage
C_per_tonne = round_money(C_route / Q)
best = argmin(C_route, затем фактический максимальный срок)
       среди полностью допустимых рассчитанных кандидатов
```

Все варианты используют одинаковые грузы, даты, массу и ограничения. Итоговая цена недопустимого/неполного кандидата — `null`. Детальные уже рассчитанные шаги остаются для объяснения причины, но не являются итогом доставки.

Налоги приводятся к единой базе запроса. Если тариф без НДС, а нужна цена с НДС: `C × (1+tax_rate)`; обратное приведение: `C / (1+tax_rate)`. Ставка обязательна при преобразовании и не зашита константой. Неизвестный налоговый состав блокирует сравнение.

Порог переключения и выгода новой схемы считаются только на сопоставимых результатах:

```text
saving = C_base − C_alternative
saving_pct = 100 × saving / C_base      при C_base > 0
```

В новом сетевом API эти две метрики и поиск порога пока не выдаются: клиент может сравнить рассчитанные альтернативы, отдельную сетку объёмов нужно считать явно. Нельзя обещать универсальный аналитический порог для ступенчатых тарифов, расписаний и мощностей.

## Свободный ввод и достаточность описания

Имя груза само по себе не меняет тариф и не задаёт плотность/опасность. До применения формул проверяются свойства, упаковка, делимость, необходимые размеры и допуск каждой услуги/хаба. Для неизвестного имени сервер возвращает уточнения; без обязательных сведений итоговая цена отсутствует. Сопоставление имени с известными свойствами — только по явному имени/синониму; произвольный груз не подменяется мукой.

Регулярные `t_i` теперь можно задавать с шагом в минутах/часах, а также днях/неделях/месяцах через `frequency.every`. Для `count` готовностей они равномерно распределяются внутри каждого интервала. Точные события — `explicit`.

Портовая годовая мощность, площадь склада и стратегические сценарии не являются новыми тарифными коэффициентами. Правила их использования: [Росморпорт](data_sources/rosmorport/README.md) и [стратегия](data_sources/strategy/README.md).
